# Commit format

The commit format shared by the `hey-mori` repositories. A repository that has
its own `docs/commit-format.md` and `scripts/validate-commit-message.sh` follows
those. They describe the same format, and the repository's validator is the
final word on what it accepts.

## Shape

```
<type>: <imperative lower-case summary>

- <what changed, or why>
- <what changed, or why>
```

## Subject

- `type` is one of `feat`, `fix`, `perf`, `refactor`, `test`, `docs`, `chore`.
  `perf` is for speed or resource use. A `refactor` must not change behaviour.
- No scope: `fix: ...`, never `fix(ledger): ...`.
- English, in the imperative ("add", "keep", "stop"), starting lower-case, with
  no trailing period.
- Aim for under 70 characters. 72 is the hard limit.
- No phase or milestone labels such as `(P2)` or `[M1]`. The branch and the
  issue carry those.

## Body

- One blank line after the subject, then a bullet list and nothing else. Every
  line starts with `- `, with no blank lines between bullets and no prose
  paragraphs.
- Each bullet makes one checkable claim about what changed or why. Three to
  seven bullets is typical.
- A trivial change, such as a typo or a broken link, may be subject-only.

## Never include

Emoji, a footer naming the tool that produced the change, `Co-Authored-By:`
lines, "Generated with" lines, pasted validation logs, or filler. Attribution
is the commit's author field.

## Commits written by git

Merge commits (`Merge pull request #N from ...`, `Merge branch '...' into ...`)
and reverts made by `git revert` keep the shape git or GitHub gives them. The
validators accept or skip them.

## What is checked, and what is a convention

Where a repository ships a validator, it runs as the `commit-msg` hook
(installed by `scripts/setup-git-hooks.sh`) and again in the repository's gate.
Every Mori validator rejects:

- a subject without an allowed `type: ` prefix, a scope, a trailing period, or
  more than 72 characters
- a body line that is not a `- ` bullet, or a blank line between bullets
- `Co-Authored-By:`, "Generated with" or "Generated by", and AI tool
  attribution
- emoji, when git runs under a UTF-8 locale (the check relies on it)

Some validators also reject the em dash, a phase marker, a capitalised
summary, or a missing blank line after the subject.

No validator can judge the rest: the imperative mood, the 70-character target,
the number of bullets, and whether each bullet is true. Reviewers check those.

## Examples

A fix:

```
fix: keep the ledger rows on screen when a reload fails

- Show the empty state only after a reload succeeds with no records
- Keep the previous rows and show the error when the reload fails
- Add a test for a failed reload that follows a successful one
```

A documentation change:

```
docs: point repository references at hey-mori

- Move GitHub paths and issue links from the old organization
- Keep registered identifiers that existing installs depend on
```

A trivial change:

```
docs: fix a broken link in the security policy
```
